# kiki — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** depuis une page web sur le téléphone, envoyer un message via ntfy.sh et l'afficher dans une bulle à gauche, par-dessus n'importe quelle app de la télé TCL.

**Architecture :** trois morceaux indépendants. `web/` (page statique sur GitHub Pages) fait un POST sur `ntfy.sh/<sujet>`. L'app Android TV `com.kiki.tv` garde un flux ntfy ouvert dans un service de premier plan et affiche une fenêtre overlay. Toute la logique pure (lecture ntfy, délais, minuterie de bulle, choix du message au démarrage) vit dans un module Kotlin JVM `core/`, testable sur le PC sans SDK Android ; le module `app/` n'est compilé que sur GitHub Actions.

**Tech Stack :** Kotlin 1.9.24, Gradle 8.7 (wrapper), Android Gradle Plugin 8.5.2, JDK 17 en CI (JDK 21 local pour `core`), JUnit 4.13.2, `org.json:json:20240303` (compileOnly/test dans `core`, fourni par Android à l'exécution), HTML/CSS/JS sans framework, GitHub Actions + Pages.

**Spec :** `docs/superpowers/specs/2026-10-22-kiki-design.md`

## Global Constraints

- Package Android `com.kiki.tv`, `minSdk = 30`, `targetSdk = 30`, `compileSdk = 34`. Nom affiché : `kiki`.
- Aucune dépendance Android lourde : pas de Compose, pas d'AppCompat, pas de bibliothèque réseau ni de coroutines. `HttpURLConnection`, `org.json`, `android.os.Handler`, threads simples.
- Aucun secret dans le dépôt public : ni sujet ntfy, ni keystore, ni mot de passe. `.gitignore` exclut `*.jks`, `*.keystore`, `local.properties`, `secret*.txt`.
- Sujet ntfy : 40 caractères `[A-Za-z0-9]`, généré une seule fois sur le PC, stocké hors dépôt dans `C:\Users\Admin-User\kiki-secret.txt`.
- Message affiché : texte nettoyé (espaces de bord retirés), 300 caractères maximum (au-delà : coupé à 299 + `…`). Message vide après nettoyage : ignoré.
- Bulle : bord gauche, centrée verticalement, largeur ≈ 1/3 de l'écran (640 px sur 1920), fond `#CC000000`, coins 24 dp, contour 2 dp `#2F80FF`, en-tête `💬 kiki · HH:MM`, pied `OK pour fermer`, fondu 200 ms. Fermeture : toute touche de télécommande ou 5 min (300 000 ms). Un nouveau message remplace l'actuel et relance les 5 min.
- Démarrage/reconnexion : ne montrer que le message le plus récent de moins de 12 h, et seulement s'il n'a pas déjà été montré (`lastShownId` persistant).
- Reconnexion : 2 s, 4 s, 8 s… plafond 300 s, remise à 2 s après une connexion réussie.
- Mémoire de kiki au repos sur la télé : < 30 Mo (PSS).
- Textes visibles en français.

## Review Focus

1. Télé qui sort de veille ou redémarre alors qu'un message déjà affiché est encore dans le cache ntfy : il ne doit **pas** réapparaître (test `pickStartupMessage ignores already shown id`, Tâche 2).
2. Message vide, uniquement des espaces, ou de plus de 300 caractères avec emojis : ignoré / coupé proprement sans couper un emoji en deux (tests `normalize`, Tâche 1).
3. Lignes ntfy qui ne sont pas des messages (`open`, `keepalive`, `poll_request`) ou JSON cassé : ignorées sans plantage (tests `NtfyParser`, Tâche 1).
4. Deux messages très rapprochés : le second remplace le premier et la minuterie repart à 5 min, sans que l'ancienne minuterie ferme la nouvelle bulle (test `replace cancels previous timer`, Tâche 2).
5. Réseau coupé longtemps puis rétabli : délais plafonnés à 300 s, puis remis à 2 s après succès (tests `Backoff`, Tâche 2).

**Interfaces :**
- Consumes : `NtfyParser`, `Backoff`, `StartupPicker`, `NtfyMessage` (core).
- Produces :
  - `class Prefs(context: Context) { var topic: String?; var lastShownId: String? }` (SharedPreferences `kiki`)
  - `class NtfyClient(topic: String) { fun poll(since: String): List<NtfyMessage>; fun stream(since: String, onMessage: (NtfyMessage) -> Unit) /* bloquant, lève IOException à la coupure */ }` — URLs : `https://ntfy.sh/<topic>/json?poll=1&since=<since>` et `https://ntfy.sh/<topic>/json?since=<since>` ; timeout de lecture 90 s (ntfy envoie un keepalive toutes les 45 s).
  - `object ListenerStatus { @Volatile var connected: Boolean }`
  - `ListenerService` : `startForeground` avec un canal `IMPORTANCE_MIN` (« kiki écoute les messages ») ; un thread unique boucle : `poll(lastShownId ?: "12h")` → `StartupPicker.pick` → afficher ; puis `stream(dernierId ?: "now")` ; sur exception : `connected=false`, attendre `Backoff.next()` ; sur connexion : `Backoff.reset()`, `connected=true`. Chaque message affiché met à jour `Prefs.lastShownId`. Sans `topic` configuré : le service s'arrête.
  - Affichage délégué à `BubbleOverlay` (Tâche 5) via une fonction `showMessage(m: NtfyMessage)` sur le thread principal (`Handler(Looper.getMainLooper())`).
  - Manifest : permissions `INTERNET`, `FOREGROUND_SERVICE`, `RECEIVE_BOOT_COMPLETED`, `SYSTEM_ALERT_WINDOW` ; `uses-feature android.software.leanback required=false`, `android.hardware.touchscreen required=false` ; `BootReceiver` sur `BOOT_COMPLETED` démarre le service.
